# ЛР1 — Nginx и балансировка

Работа проверяет, как Nginx принимает HTTPS, выбирает backend и применяет правила к разным URL. Открытая страница сама по себе не подтверждает ни балансировку, ни защиту: для них нужны отдельные запросы.

## Конфигурация

Nginx раздаёт статический frontend по HTTPS, проксирует `/api` на два Flask-контейнера, отдаёт отдельный файл через `alias`, разводит два виртуальных хоста и ограничивает запросы к API. TLS-сертификат и пароль Basic Auth сгенерированы только для локального стенда и находятся в `.local/nginx/` (каталог в `.gitignore`). Порты хоста привязаны к loopback: HTTP 8080 и HTTPS 8443; внутри контейнера Nginx слушает 80 и 443.

## Проверка после ревью

Без пароля `/admin` вернул 401. Этот ответ подтверждал ровно одно: данный маршрут требует авторизацию. Формулировку «админка защищена» пришлось проверять отдельно — та же HTML-страница открылась через `/assets/admin/index.html` с 200. Новых прав у запроса не появилось; он попал под широкий `alias`, разрешавший выдачу вложенных файлов.

В таком устройстве пароль усложнял жизнь тому, кто пользовался предусмотренным входом. Проверяющему хватило уточнить адрес. Самый длинный URL оказался самым коротким способом попасть в админку. Поэтому исправление касается выдачи файла: Nginx и Flask разрешают в `/assets` только `app.js` и `styles.css`; оба запрещённых вложенных пути теперь возвращают 404. Проверка одного красивого 401 перестала подменять проверку самой страницы.

### Смена адреса backend

В отдельной временной сети проверено обновление адреса upstream: после замены backend `172.23.0.10` на `172.23.0.11` первый запрос во время обновления DNS истёк по трёхсекундному таймауту, следующий вернул 200 с `X-Upstream: 172.23.0.11:80` без reload Nginx. В этом fixture использовался DNS TTL 2 с; проверка показывает повторное обнаружение нового адреса после короткой паузы, а не отсутствие перебоя. Сценарий сначала ограниченно ждёт готовности исходного backend; затем создаёт и удаляет только собственные контейнеры и сеть.

## Ограничения замера

Сертификат самоподписанный и предназначен только для локальной проверки. При использовании хостовых портов 8080/8443 редирект указывает на HTTPS-порт 8443, а не на публичный 443; внутри контейнера Nginx принимает HTTP 80 и HTTPS 443. Балансировка и отказ проверены на локальном Compose-стеке; внешняя доступность не заявляется.

Короткий burst дал 20 ответов 429 из 24 — лимит отклонил часть запросов, как и требовалось. При обычном темпе наблюдались ответы обоих backend; после остановки `backend2` ответил `backend-1`. Порог `5r/s` и burst `3` относятся к учебному стенду. DNS-опыт отдельно подтвердил нахождение нового IP без reload, но включал таймаут: балансировку, восстановление адреса и непрерывную доступность нельзя объединять в одно обещание.
