# ЛР1* — три ошибки конфигурации Nginx

На основном локальном Nginx проверены доступ к dotfile, path traversal и обращение к `/admin` без авторизации. Запросы вернули 404, 400 и 401; [фактические результаты 28 октября 2026 года](evidence/2026-10-28-live-nginx-checks.txt) и границы проверки разобраны в [отчёте](report.md).

Дополнительный изолированный стенд воспроизводит три заранее подготовленные ошибки: path traversal через `alias`, листинг каталога и выдачу dotfile.

Запуск из корня проекта:

```sh
./scripts/lab-01-star-check.sh
```

Скрипт собирает временную копию fixture-файлов, не исключённых `.gitignore`, подставляет в неё `/.env` из тестового шаблона `fixtures/test-env.fixture`, создаёт собственные сеть и контейнер Nginx и назначает контейнеру свободный порт только на `127.0.0.1`. Локальный игнорируемый `.env` не копируется и не используется. После трёх запросов скрипт удаляет контейнер, сеть и временную копию. Конфиг не подключён к основному Compose; шаблон содержит только фиктивную тестовую строку.

Для основного сервиса `/.env` должен быть закрыт. Здесь ожидается HTTP 200 с тестовой строкой. Если по привычке добавить запрет, скрипт пожалуется — у него украли уязвимость. Исправления применяются к рабочей конфигурации, а этот образец нужен, чтобы плохое поведение можно было воспроизвести и распознать.
