# ЛР0 — журнал задач и отдельная PostgreSQL

## Идея

«Полевой журнал» хранит учебные задачи. Для ЛР0 важен весь путь одной записи: форма в браузере → HTTP API → отдельная PostgreSQL → повторное чтение через API. Строка, появившаяся на экране, ещё может быть всего лишь хорошей памятью открытой вкладки. Поэтому проверка продолжается после обновления страницы и перезапуска БД. Тема сервиса — наш выбор; требования Л0 задаёт методичка.

Ниже описан запуск версии ЛР0, зафиксированной в [коммите `1c7c8d7`](https://github.com/fadeeey/clouds-labs/commit/1c7c8d7): PostgreSQL работает в контейнере, Flask — в локальном Python-окружении. Для точного воспроизведения нужны README и `compose.yaml` именно этой ревизии.

## Запуск и проверка

Из корня `clouds-labs/`:

1. Скопируйте `.env.example` в `.env` и замените локальный пароль на свой.
2. Запустите отдельную БД: `docker compose up -d db`; дождитесь `healthy` командой `docker compose ps`.
3. Создайте окружение Python и установите зависимости:

   ```sh
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

4. В этом же shell загрузите переменные без вывода секрета и запустите backend:

   ```sh
   set -a
   source .env
   set +a
   python app/backend/server.py
   ```

5. Откройте `http://127.0.0.1:5000`, добавьте задачу, обновите страницу. Задача должна остаться: `GET /api/tasks` читает её из PostgreSQL.
6. Перезапуск БД без `-v` сохраняет именованный том: `docker compose restart db`; после восстановления `/health` и список должны отвечать.

Интеграционные проверки против реально запущенной БД: `python -m unittest discover -s tests -v`.

`GET /health` проверяет доступ к БД запросом `SELECT 1`; `GET /live` проверяет только процесс приложения. База слушает только localhost на порту 5433. `docker compose down` останавливает сервисы, но сохраняет том. Чтобы намеренно удалить данные, используйте `docker compose down -v`.

После добавления задачи хороший результат выглядит подозрительно скромно: обновили страницу — та же строка; перезапустили PostgreSQL — снова она. Для зрелищной демонстрации полезнее было бы что-нибудь потерять. Но тогда пришлось бы демонстрировать уже другую лабораторную. Здесь отсутствие перемен на экране подтверждается новым чтением из БД.

## Части приложения

- Frontend: `app/frontend/` — HTML, CSS и JavaScript; браузер отправляет запросы на том же origin.
- Backend: `app/backend/server.py` — Flask отдаёт страницу и обрабатывает `/api/tasks`.
- Database: контейнер PostgreSQL с отдельным именованным томом; SQLite не используется.

## Отчёт и доказательства

В [отчёте ЛР0](report.md) сохранены снимок созданной задачи, результат трёх интеграционных тестов с реальной PostgreSQL и наблюдения после перезапуска БД. Проверка пустой строки отдельно подтверждает отказ API записывать задачу из пробелов. `.env`, локальные пароли и дампы с личными данными в доказательства не входят.

## Ограничения

Для этого запуска нужна работающая Docker Desktop. Минимальный Compose версии ЛР0 поднимает только PostgreSQL: здесь не проверялись контейнеризация приложения, Nginx или CI. Три части приложения не означают три контейнера.
