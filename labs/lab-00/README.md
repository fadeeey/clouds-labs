# Лаба 0 — свой сервис

## Идея

«Полевой журнал» — список учебных задач, чтобы показать полный путь записи: браузер → HTTP API → отдельная PostgreSQL. Тема сервиса — наш выбор; требования Л0 задаёт методичка.

Состояние проекта при проверке ЛР0 зафиксировано в [коммите `1c7c8d7`](https://github.com/fadeeey/clouds-labs/commit/1c7c8d7). Для точного воспроизведения этой версии используйте её README и `compose.yaml`.

## Запуск и проверка

Из корня `clouds-labs/`:

1. Скопируйте `.env.example` в `.env` и замените локальный пароль на свой.
2. Запустите отдельную БД: `docker compose up -d db`; дождитесь `healthy` командой `docker compose ps`.
3. Создайте окружение Python и установите зависимости:

   ```sh
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

4. В этом же shell загрузите переменные без вывода секрета и запустите backend:

   ```sh
   set -a
   source .env
   set +a
   python app/backend/server.py
   ```

5. Откройте `http://127.0.0.1:5000`, добавьте задачу, обновите страницу. Задача должна остаться: `GET /api/tasks` читает её из PostgreSQL.
6. Перезапуск БД без `-v` сохраняет именованный том: `docker compose restart db`; после восстановления `/health` и список должны отвечать.

Интеграционные проверки против реально запущенной БД: `python -m unittest discover -s tests -v`.

`GET /health` проверяет доступ к БД запросом `SELECT 1`; `GET /live` проверяет только процесс приложения. База слушает только localhost на порту 5433. `docker compose down` останавливает сервисы, но сохраняет том. Чтобы намеренно удалить данные, используйте `docker compose down -v`.

## Части приложения

- Frontend: `app/frontend/` — HTML, CSS и JavaScript; браузер отправляет запросы на том же origin.
- Backend: `app/backend/server.py` — Flask отдаёт страницу и обрабатывает `/api/tasks`.
- Database: контейнер PostgreSQL с отдельным именованным томом; SQLite не используется.

## Отчёт и доказательства

Добавьте проверяемые скриншоты формы до и после сохранения и после обновления страницы; опишите запуск, запись в БД и наблюдаемые проверки. Не публикуйте `.env`, пароли или дампы с личными данными. В отчёте отдельно перечислите, что проверено, и что не удалось проверить. Сами скриншоты добавляйте только после реального запуска.

## Ограничения

Перед первой проверкой нужна работающая Docker Desktop. Этот минимальный compose-файл поднимает только PostgreSQL и сам по себе не означает выполнение ЛР2.
