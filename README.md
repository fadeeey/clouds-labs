# DevOps — журнал лабораторных

Небольшой журнал учебных задач на Flask и PostgreSQL. Семь лабораторных проверяют его с разных сторон: как сохраняется запись, собирается образ, ограничиваются ресурсы, защищаются маршруты и восстанавливается релиз.

По мере работы слово «работает» стало требовательнее. Сначала хватало увидеть задачу в браузере. В последней проверке пришлось предъявить её id, заголовок и тот же том БД после намеренно сломанного релиза. У списка дел появилась процедура восстановления. У самих дел поводов исчезнуть заметно поубавилось.

## Устройство

![Текущая схема: браузер → Nginx → два Flask backend → PostgreSQL](docs/architecture.svg)

В текущем Compose четыре сервиса: Nginx со статическим frontend, два экземпляра Flask backend и PostgreSQL. Nginx принимает HTTPS и распределяет API-запросы; оба backend через psycopg работают с одной БД. Данные находятся в именованном томе, отдельно от жизненного цикла контейнеров.

## Результаты

![Сравнение плохой и исправленной Docker-сборок: размер образа 401.9 и 51.1 MiB; повторная сборка 7.16 и 0.31 секунды](docs/docker-build-comparison.svg)

Один ARM64-замер на ревизии [`e4e356f`](https://github.com/fadeeey/clouds-labs/tree/e4e356f): `.Size` локального образа и повторная сборка после изменения HTML. [Методика и исходные значения](labs/lab-02/report.md).

Размер образа и время повторной сборки отвечают на разные вопросы. В плохом Dockerfile изменение HTML заставляло снова устанавливать зависимости; в исправленном их слой оставался в кэше. Уменьшение `.Size` связано со всей переработкой образа, а не с одним удачно расставленным `COPY`. Числа на схеме — исторический замер, не результаты текущего HEAD.

### CI и откат

Схема pipeline: `lint → PostgreSQL tests → build → Trivy → GHCR → deploy smoke`; [успешный run #39495550006](https://github.com/fadeeey/clouds-labs/actions/runs/39495550006).

- Негативный тест завершился ошибкой; build и deploy были пропущены в [run #39495954222](https://github.com/fadeeey/clouds-labs/actions/runs/39495954222).
- Образ с 16 Critical остановил публикацию и deploy в [run #39496087533](https://github.com/fadeeey/clouds-labs/actions/runs/39496087533). В обычных образах Critical — 0; остаются 48 High у backend и 45 High у frontend. Четыре Python-находки backend остаются неустранёнными; детали и ограничения сканирования — в [отчёте ЛР3](labs/lab-03/report.md).

| Рабочий релиз | Неисправный frontend | Откат |
|---|---|---|
| HTTP 200 | HTTP 503, unhealthy | HTTP 200 |
| Контрольная запись с id=1 | Тот же том БД | Та же запись с id=1 |

После отката HTTP 200 ещё не завершает приёмку: `SELECT 1` сработал бы и в новой пустой БД. В этом опыте API вернул ту же контрольную задачу `id=1` с тем же заголовком; совпали и идентификаторы backend/БД, и том. Интервал от команды rollback до health и контрольной записи составил 0,552 с в [run #39499120264](https://github.com/fadeeey/clouds-labs/actions/runs/39499120264). Это один запуск с откатом только frontend, без миграции схемы.

Hosted deployment временный: после smoke test стенд очищается. Сервис умеет сохранять задачи; выполнять их всё ещё приходится отдельно. Ни балансировка, ни откат пока не нашли к этому уязвимость.

## Запуск

Нужен Docker Desktop с Docker Compose. Локальные сертификат и Basic Auth создаются в `.local/nginx/`, эта папка исключена из Git.

```sh
cp .env.example .env
# Замените POSTGRES_PASSWORD локальным паролем.
./scripts/lab-01-setup-local.sh
docker compose up --build --wait -d
```

Откройте <https://localhost:8443>. Сертификат самоподписанный. Готовность API и PostgreSQL: `curl -kfsS https://localhost:8443/healthz`.

```sh
docker compose down
```

Не добавляйте `-v`, если нужно сохранить данные в именованном томе PostgreSQL.
